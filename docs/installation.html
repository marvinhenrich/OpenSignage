Installation

Ein Befehl, dann läuft es.

Voraussetzungen

Ein Linux-Server mit Docker und Docker Compose. Sonst nichts — weder Node noch eine Datenbank müssen vorhanden sein, beides bringt der Stapel mit.

Starten

git clone https://github.com/marvinhenrich/OpenSignage.git
cd OpenSignage
docker compose up -d

Danach https://<Serveradresse> aufrufen. Mehr ist nicht nötig: es gibt keine Datei, die vorher bearbeitet werden muss.

Was beim ersten Start automatisch passiert

GeheimnisseFür diese Installation werden eigene Zufallswerte erzeugt und im Datenträger secrets abgelegt. Es gibt kein ausgeliefertes Standardkennwort.
TLSLiegt kein Zertifikat vor, wird ein selbstsigniertes für zehn Jahre erzeugt.
DatenbankSchema wird angelegt und bei Updates automatisch mitgewandert.
AdministratorBenutzer admin mit Zufallskennwort, das einmalig im Protokoll steht.

Zugangsdaten abholen

docker compose logs cms | grep -A3 "ADMIN-BENUTZER"

Nach der ersten Anmeldung ändern. Das erzeugte Kennwort steht im Protokoll und bleibt dort, bis die Protokolle rotieren.

Eigenes Zertifikat

Das selbst erzeugte Zertifikat ist ein funktionierender Startpunkt, kein Ersatz für ein richtiges. Wer eine interne Zertifizierungsstelle betreibt, legt server.crt und server.key in den Datenträger certs — dann wird nichts erzeugt.

Bei Kiosk-Betrieb muss das Zertifikat auf den Anzeigegeräten als vertrauenswürdig hinterlegt sein. Das Kiosk-Paket erledigt das mit.

Optionale Einstellungen

Alles Weitere ist freiwillig und steht in .env.example. Ohne diese Datei laufen sinnvolle Vorgaben.

EinstellungWofür
PUBLIC_URLAdresse in Einladungslinks und im Kiosk-Paket
BRAND_NAME, BRAND_VENDORName der Anlage in Oberfläche und Dokumenten
BRAND_SLUGOrdner- und Aufgabennamen auf den Windows-Geräten. Nachträglich ändern bricht bereits installierte Geräte.
AD_DCS, AD_UPN_SUFFIXAnmeldung gegen Active Directory. Leer = nur lokale Konten.
ICINGA_URL, ICINGA_API_USERMonitoring-Kachel. Bitte einen Benutzer mit nur Leserechten anlegen.
